title: Server SDK
description:
  Framework-neutral authenticated WebSocket sessions and job delivery
  primitives.
---

`@openprinter/server` attaches to an existing Node-compatible HTTP
server. It authenticates agent connections, validates protocol
messages, tracks live sessions, runs heartbeat checks, and exposes
typed lifecycle callbacks.

```ts
import { createOpenPrinterServer } from '@openprinter/server';

const openPrinter = createOpenPrinterServer({
  authenticateAgent: async ({ token, request }) => {
    const agent = await verifyAgentToken(token, request);
    return agent
      ? {
          agentId: agent.id,
          metadata: { organizationId: agent.organizationId },
        }
      : null;
  },
  onPrintersChanged({ agent, printers }) {
    inventory.replace(agent.agentId, printers);
  },
  onJobReceived({ agent, message }) {
    jobs.markReceived(agent.agentId, message.payload.jobId);
  },
});

httpServer.on('upgrade', openPrinter.handleUpgrade);
```

## What the SDK owns

- WebSocket upgrade and Bearer authentication
- version negotiation and runtime validation
- one active session per agent ID
- bounded heartbeat and message size handling
- typed inbound lifecycle callbacks
- server-to-agent message delivery
- structured offline and protocol errors

## What the host owns

- durable jobs and retry schedules
- database, Redis, or queue choice
- agent authorization policy and token format
- tenant or organization models
- logical printer routing
- billing and user sessions

Every job callback is structurally validated, but the host must still
match its agent, correlation, job, and idempotency identifiers against
the durable application record before changing that record. Those
correlations outlive an in-memory SDK session and therefore cannot be
authorized by the SDK alone. Lifecycle callbacks have a bounded
execution time (`callbackTimeoutMs`, five seconds by default);
failures and timeouts are isolated through `onCallbackError`.

When an agent is offline, `send` returns a structured unavailable
result. Invalid outbound protocol values still throw a typed protocol
error. The SDK never silently creates a durable queue.
