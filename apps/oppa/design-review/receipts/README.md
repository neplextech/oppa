# Thermal receipt presentation review

The screenshots in this directory are actual Chrome renders of OPPA's virtual
printer workspace. Capture fixtures were generated by the Rust structured-document
encoder, ESC/POS interpreter, and monochrome rasterizer; there is no HTML receipt
content renderer in this review.

## Changes

- Receipt presentation uses theme-independent warm paper, a restrained shadow,
  a cut-request edge, and equal 16 px decorative padding on all four sides.
  The framing sits outside the source raster and never compresses it. Dimension
  labels describe the captured raster. Raw raster removes every decoration.
- Thermal captures start at 100% CSS physical scale. Fit window only shrinks;
  Fit width and manual zoom retain explicit enlargement. Long outputs scroll.
- Physical 58/80 mm raster paper contains centered 384/576-dot printable areas
  at 203 DPI, consistent with the encoder's 32/48 columns. The existing licensed
  font8x8 bitmaps remain, with monochrome Font A cell sizing. This is a generic
  simulation, not a specific hardware font ROM.
- Feed spans and requested cutter positions come from the same raster layout
  pass. They add no ink or commands. Office cut semantics remain unchanged.
- Thermal PNG projection preserves full resolution within the existing 4 MiB
  capture projection budget. Office previews keep their bounded dimensions.
  Exported bytes do not depend on theme, presentation mode, padding, or zoom.
- Local capture metadata records the paper width and operation positions.
  Retained event memory counts against the bounded history; at most 256 operation
  annotations are drawn. No protocol fields or original payloads are changed.

## Validation

- Full workspace formatting, ESLint/Clippy, type checks, JavaScript/Rust tests,
  and build passed. Final native projection tests and frontend padding checks
  also passed after the final adjustments.
- Three Rust regression tests cover printable margins, encoder column wrapping,
  multiple resolutions, binary pixels, feed/cut positions, no-ink cut behavior,
  images, QR, barcodes, and long receipts. A native projection regression verifies
  full-resolution thermal export alongside bounded office previews.
- Three zoom unit tests plus the existing five onboarding tests passed.
- Browser runner passed 128 layouts: four real raster fixtures × two themes ×
  two window sizes (800×600 and 1280×800) × two presentation modes × four zoom
  modes. It checks page overflow, equal padding, preserved actual-size image
  width, fit bounds, scrolling, unchanged PNG downloads, and office navigation.
- Native window execution and physical printer acceptance were not exercised.
  CSS physical sizing depends on desktop display scaling. The existing Vite
  chunk-size warning remains.
